Part of #271 (ships first, per the issue's own shipping requirement: the warning and the baseline land before the prompt freeze, which follows in a separate PR).

## What & why

A prompt prefix that keeps changing between turns is invisible today: each turn re-pays the cache write and the dashboard just shows tokens. This PR adds the observable signature — a rolling warning in the Session's context card when cache writes exceed cache reads across consecutive turns — plus the measurement instrument used to record the baseline the prompt-freeze PR will be judged against.

## Fix

- **Shared** (`apiResponses.ts`): `SessionResponse` gains `recentCacheTurns: SessionCacheTurn[]` (`{ readTokens, writeTokens }`, oldest last) — the seed for the warning on page load, where the live `usage_update` stream has no history. Named on both sides per ADR-0040; `client.contract.test-d.ts` passes.
- **Server**: `SessionManager.getRecentCacheTurns(id, limit = 5)` reads `usage_events`' per-turn cache columns, agent turns only (`purpose = 'turn'` — judge calls have their own one-shot prefix and would pollute a consecutive-turn signal). Served by `GET /api/sessions/:id`; the two POST creators send `[]`.
- **Web**: `useSessionCacheTurns` seeds from the envelope and extends live — the turn-end `usage_update` carries the turn's full usage in its `usage` field (only `cumulative` is rewritten server-side, and the cache columns survive there), so each reconciling event appends one turn wholesale. `cacheInstabilityWarning(turns)` (lib/cache-health.ts, pure): true when the last 2 completed turns each paid more in writes than reads — two is the smallest honest "consecutive turns": one cold start re-paying a prefix is normal, two in a row is the fingerprint of a prefix that keeps changing. `ContextPanel`'s Current-session card renders a quiet amber line naming the fingerprint and the likely cause, and renders nothing on a healthy cached Session.

## The measurement instrument + baseline

- `scripts/cache-spy.mjs` (+ module hook, + sandbox stub): a fake Anthropic provider loaded into the server process via `NODE_OPTIONS="--import"` that **simulates prefix caching from the requests dilna actually sends** — it hashes each cumulative message boundary of every request (cache_control bookkeeping stripped; providers match on content), reports `cache_read` for the longest previously-seen boundary and `cache_write` for the rest, and persists its boundary table across restarts (a real provider's cache outlives dilna's process — that is the mechanism under test).
- `scripts/measure-cache-stability.mjs`: boots an isolated instance against the spy, drives **three real turns with a real `read` tool call**, restarting the server between turns and enabling a new Repo skill before each respawn (the current code rebuilds the system prompt from `formatSkillsPrompt(repoSkills)` at every spawn — see the freeze PR for why skills, not titles, are the real drift source). Per-turn cache split comes from dilna's own `usage_events`.

**Baseline (before the prompt freeze), main @ dad0beb, this exact script:**

| turn | read | write | total(prompt) | re-paid |
|---|---|---|---|---|
| 1 | 1,040 | 11,118 | 12,158 | 91% |
| 2 | 11,237 | 21,315 | 32,552 | 65% |
| 3 | 21,396 | 31,474 | 52,870 | 60% |

`consecutive write-dominant turns: 3 → warning FIRES`. Round-level spy data shows the fingerprint precisely: the first request after each restart has `read = 0` — the entire prefix is re-paid because the rebuilt prompt (new skill enabled) invalidates it — exactly what the freeze removes. The freeze PR re-runs this script and prints the after-figure alongside.

## Tests

## Verification

- `tsc --noEmit` on all three packages; `biome check .` exit 0; web vitest suite green.
- The harness itself was validated end-to-end: the table above is real output, driven through the real server, real tool execution, and real persistence.

## Decisions

- **Window = 2 consecutive turns** — small enough that the cold-start drift scenario trips it without a long setup, large enough that a single legitimate cold start (idle kill, restart, compaction respawn) stays quiet.
- **Agent turns only** in the seed — the warning is about the Session's prompt stability; judge calls (ADR-0046) don't share that prefix.
